one probelm: ai loves to do the tasks horizentally, for exp it first builds the whole schema, the whole repo, the whole service and then the whole api. the prblem is that with this approach we wont get feedback of each process for a long time. better approach is to do the task vertically.for exmp one part of schema,its repo,service and finally api. so you will get an imidiate feedback of what has implemented instead of using a greate number of tokens and then find the issues
* kanban board is better than normal vertical graph(or sequential plan) because in kanban board there are some dependecy tasks an some tasks that can be done parallel after those depency tasks is done. so we can run mlutiple agents to implement multiple services simtansuoly.
