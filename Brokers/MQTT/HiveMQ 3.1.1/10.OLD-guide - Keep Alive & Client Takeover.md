mqtt establish tcp connection between broker and client. if tcp dissconect, LWT helps to have the state of the broker, but there are situation that TCP half disconnects! meaning one side knows the connection has disconnected but the other side doesn't so we need keep alive mechanism

in connect packet we set the keepalive duration and if the broker doesn't hear anything from the client, it will discconect the connection. but in the mean while there are  a ping-pong pacakets with no payload that ensure the connection between broker and the client is open and both are aware of being connected.
keep alive can be increased up to 18 hours.
also you can disable it which is not recommended

client takeover:
when the client half disccoenct the TCP connection and the broker doesn't know, when the client try to establish a new tcp connections, the broker will dissconet the old one and use the new one. client take over!

best practises:
	1- Use unique ClientIds otherwise if you use same clientids for different devices, when those clients connects the broker assume its the same client with new tcp connection and active client take over mechansim
	2- always authenticate clients to prevent unwanted client takeovers, because if you don't authenticate, if someone get access to specific client id,it can takeover. so always use proper authentication!  use password pairs or better ssl/tls certificate or use other features
