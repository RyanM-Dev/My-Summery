Explain and apply the central idea of Chapter 3: Software Architecture.

Understand the idea

Choosing PostgreSQL is an architectural decision about data ownership, consistency, operations, and application boundaries. Learn to use the official documentation as a technical reference and evaluate trade-offs against the system's requirements instead of choosing a database by fashion. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Small practice

Use a disposable schema or safe sample data to apply Software Architecture. Predict the outcome, then check one boundary case and explain what PostgreSQL guarantees.

Practice

For one backend feature, list its consistency needs, data owner, failure modes, and operational trade-offs before choosing the database boundary.

Do not infer performance from a tiny table or correctness from one happy-path row. Choose evidence that exposes the behavior you are learning.
