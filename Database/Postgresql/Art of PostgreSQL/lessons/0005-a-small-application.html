Understand the idea

Follow a small music-catalog application from its README and schema to real queries such as listing albums by artist or finding top artists by genre. It demonstrates how application requirements become parameterized SQL over related tables. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Small practice

Use a disposable schema or safe sample data to apply A Small Application. Predict the outcome, then check one boundary case and explain what PostgreSQL guarantees.

Practice

Plan a small music-catalog endpoint: choose result columns, join keys, a parameter, and deterministic ordering before writing the query.

Do not infer performance from a tiny table or correctness from one happy-path row. Choose evidence that exposes the behavior you are learning.
