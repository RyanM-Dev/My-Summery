Understand the idea

Retrieving data begins with choosing the rows and columns that answer a question. Practice SELECT, filtering, and reading from one relation before combining data. Build a result set that returns only the needed fields and rows; this reduces transfer and clarifies the contract with the application. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Worked example

SELECT id, created_at, total
FROM orders
WHERE created_at >= DATE '2026-01-01'
ORDER BY created_at, id
LIMIT 20;

This returns a bounded, explicitly ordered result instead of transferring every row to application code.

Practice

Rewrite a broad SELECT so it returns only the fields and rows needed by a backend response.

Do not infer performance from a tiny table or correctness from one happy-path row. Choose evidence that exposes the behavior you are learning.
