Understand the idea

SQL statements have different roles: DML changes rows, DDL changes schema, TCL controls transactions, and DCL controls access. Knowing the category helps you reason about transaction boundaries, migration safety, and permissions. A query is not merely a string; it participates in a deployment and security model. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Worked example

BEGIN;
UPDATE inventory SET quantity = quantity - 1 WHERE sku = 'A-17';
COMMIT;

This illustrates transaction control around a data change. Production logic should check that exactly the intended row was updated and enforce valid quantities with constraints.

Practice

Classify table creation, row modification, transaction commit, and a role grant as DDL, DML, TCL, or DCL.

Do not infer performance from a tiny table or correctness from one happy-path row. Choose evidence that exposes the behavior you are learning.
