Understand the idea

Ordering is a real operation with a cost. `LIMIT` can enable top-N plans; deep `OFFSET` pagination still requires the server to find and skip earlier rows. Keyset pagination uses a stable ordering key to continue from the last seen row. The unique `id` breaks timestamp ties so pagination has a deterministic continuation point. Worked example

SELECT id, created_at
FROM orders
WHERE (created_at, id) < ($1, $2)
ORDER BY created_at DESC, id DESC
LIMIT 25;

This keyset pattern continues from a stable cursor and avoids scanning a large OFFSET. The unique id resolves timestamp ties.

Practice

Fetch a later page of results using a stable cursor tuple and unique tie-breaker instead of a large OFFSET.
