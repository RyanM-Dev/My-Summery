Understand the idea

`NULL` represents missing or unknown information, so ordinary comparisons can yield `UNKNOWN` rather than true or false. This affects filters, joins, constraints, aggregates, and application decoding. Use `IS NULL` and `IS NOT NULL`; use `COALESCE` only when substituting a value is semantically correct. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Worked example

SELECT id
FROM customers
WHERE email IS NULL;

Use `IS NULL` for missing values. `email = NULL` evaluates to unknown, so it does not select the row.

Practice

Evaluate a comparison involving NULL. Rewrite it with IS NULL or IS NOT NULL and explain the three-valued result.

Do not infer performance from a tiny table or correctness from one happy-path row. Choose evidence that exposes the behavior you are learning.
