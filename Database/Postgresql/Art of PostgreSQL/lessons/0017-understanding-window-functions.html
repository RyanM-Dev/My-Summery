Understand the idea

Window functions calculate across related rows without collapsing them into one row per group. `PARTITION BY` defines independent groups; `ORDER BY` defines sequence; the frame determines which nearby rows participate. They support ranking, running totals, moving averages, gaps-and-islands, sessions, and cohort analysis. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Worked example

SELECT account_id, occurred_at, amount,
       sum(amount) OVER (PARTITION BY account_id ORDER BY occurred_at, id
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM ledger_entries;

The window keeps every ledger row while calculating a cumulative value within each account.

Practice

Calculate a running total per account with an explicit window frame. Check how tied timestamps affect order.
