Understand the idea

Attribute values and domains shape what a relation can represent. A type is more than storage: it defines valid operations and comparison behavior. Better domain choices can move correctness checks from convention into the schema. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Small practice

Use a disposable schema or safe sample data to apply Some Relational Theory. Predict the outcome, then check one boundary case and explain what PostgreSQL guarantees.

Practice

Define a constrained domain value such as a positive quantity. List valid and invalid values before writing the schema.

Do not infer performance from a tiny table or correctness from one happy-path row. Choose evidence that exposes the behavior you are learning.
