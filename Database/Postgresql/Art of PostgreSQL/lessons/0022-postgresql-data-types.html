Understand the idea

Use types that represent the domain: booleans for truth values, numeric types for exact quantities, UUIDs for identifiers when appropriate, timestamp types with deliberate timezone semantics, network types for addresses, and ranges or multiranges for intervals. This exclusion constraint prevents overlapping reservations for the same room. It requires the appropriate GiST operator support. **Version note:** The official 2026 contents call out multiranges (PostgreSQL 14+) and `C.UTF-8` collation support in PostgreSQL 17. Confirm server-version availability before adopting a feature. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Worked example

CREATE TABLE reservations (
  room_id bigint NOT NULL,
  occupied daterange NOT NULL,
  EXCLUDE USING gist (room_id WITH =, occupied WITH &&)
);

The range type and exclusion constraint encode a domain rule: reservations for one room may not overlap.

Practice

Model a room reservation as a date or timestamp range. State boundary and timezone semantics, then reject an overlap.

Do not infer performance from a tiny table or correctness from one happy-path row. Choose evidence that exposes the behavior you are learning.
