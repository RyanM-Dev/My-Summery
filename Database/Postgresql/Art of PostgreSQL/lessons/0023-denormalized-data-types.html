Understand the idea

Arrays, composite types, XML, JSON/JSONB, and enums can represent structured or constrained values. JSONB is useful for flexible attributes and operators, but it does not remove the need to model stable relationships and frequently queried fields deliberately. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Worked example

CREATE TABLE events (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, payload jsonb NOT NULL);
CREATE INDEX events_payload_gin_idx ON events USING gin (payload);
SELECT id FROM events WHERE payload @> '{"kind": "payment"}';

JSONB operators and index operator classes must match the workload. Keep stable relationships and frequently constrained attributes relational where that improves integrity.

Practice

Store a flexible event in JSONB. Identify which fields should become typed columns or constraints because they are stable or frequently queried.

Do not infer performance from a tiny table or correctness from one happy-path row. Choose evidence that exposes the behavior you are learning.
