Understand the idea

Normalization reduces update, insertion, and deletion anomalies by representing each fact in a coherent place. Keys and constraints then define identity and valid relationships. PostgreSQL constraints include primary keys, foreign keys, `NOT NULL`, `CHECK`, domains, exclusion constraints, and row-level security policies. Start with the result the application needs or the rule the database must protect. Choose a PostgreSQL feature that expresses that requirement, then identify evidence that would show it is correct.

Worked example

CREATE TABLE orders (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  customer_id bigint NOT NULL REFERENCES customers(id),
  total numeric(12,2) NOT NULL CHECK (total >= 0)
);

The key, foreign key, and check constraint protect the invariant for every writer, not just one application path.

Practice

Normalize a repeated customer address out of order rows. Add keys and explain which update anomaly the design prevents.

Do not infer performance from a tiny table or correctness from one happy-path row. Choose evidence that exposes the behavior you are learning.
