before containers:
we had to install most of the services and dependencies on the server our selves on each server or os. and based on the os the process was different
we have ultiple steps of installation that could go wrong if one or more comand entered wrong or not based on the correct process.

the process: we had the artifact and a set of instruction on how to set it up on the server that was handed to the operation team to do the deployment. the proble was that we need to configure and install everything on the server which can cause different problem like dependency version conflicts or we would have problem if we want to have different version of a service on the same enviroment.
also misunderstanding could happen between development and operation team that could take extra process and time back and forth


with containers:
we do not have to install any service directly because container has an isolated os layer which it will install servies and pacakges there.

we only need to check what image we need in container repo and use it for our process. 
with one command we can run and install a lot of services and depenceies and run the app

we also can run different versions of application on the same enviroment without having any conflicts
with container this process is simplfied because we the whole package in one simple configuration with enviroment configuration needed on server

we only need to install docker and thats all

beside docker, we have containerD crio and etc

container consist of layers of images and mostly the base image is a linux os like alpine or other distro because of their small size and ...

on top of that we have application image but usually there are different other images in between these two layer
