1-use offical docker images as base image where it is available, like using node image than using ubuntu image and install node on it because the official image is made besd on best practises

2- do not use latest tag! because after each build it might get a new version that might break stuff. so latest tag is unpredictable

3-  do not use images based on full blown OS like ubuntu,centos and .. because they are greater in size, comes with uncessary tools and also because of their great number of tools it comes with broader vunelberties issues. so its better to use a leaner and smaller os distro like alpin linux and it comes with far btter security

4- optimise docker caching, re order docker commands in docker file in this pattern: from least changed to the most frequently changed so if some part changes, docker wont invalidates the image caches and download them all again

old version:
```Dockerfile
FROM node:20

WORKDIR /app

COPY myapp /app

RUN npm install --production

CMD ["node", "src/index.js"]
```


new version :
```Dockerfile
FROM node:20

WORKDIR /app

COPY package.json package-lock.json

RUN npm install --production

COPY myapp /app

CMD ["node","src/index.js"]
```

now when sth in pacakge. json changes , 
pull node alpine image from cache
set working directory from cache

copy package.json cache invalidated
install dependencies cache invalidated
copy project files cache invalidated

and when things in code changes:
pull node alpine image from cache
set working directory from cache

copy package.json from cache
install dependencies from cache
copy project files cache invalidated

and only one layer cache will be invalidated

7- which OS user will be used to start the application? its bad security if the container uses root user because it is security bad practise.
the beste practise is to create a dedicated user and group in the docker image to run the application:

```Dockerfile
...

RUN groupadd -r tom && useradd -g tom tom

RUN chown -R tom:tom /app

USER tom

CMD node index.js
```

some images like node use a generic user (node user) so we don't have to create a node user ourself
