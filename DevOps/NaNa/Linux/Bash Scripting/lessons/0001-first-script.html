Your one skill

Launch the same script in two different ways

A Bash script is a text file of commands. The shebang at the top selects Bash when Linux launches the file directly; when you type bash report.sh, you already chose the interpreter.

The Bash manual confirms both behaviors: Bash can read a script as its input, or the executable file can name its interpreter in the first line. Read: Shell Scripts.

You choose Bash bash report.sh

Bash reads the file. The shebang and execute permission are not needed for this launch form.

Linux follows the file ./report.sh

The file needs execute permission. Linux reads its shebang to find the interpreter.

With #!/usr/bin/env bash, the system uses env to find Bash through PATH. The script still runs from your current working directory, so a relative path inside it starts there—not automatically beside the script.

Scripts run as non-interactive shells. Bash’s startup-file rules differ from an interactive terminal, which is one reason a command can work in your terminal but fail in CI. Read: Bash Startup Files.

Three-minute practice

Build a host report

Use a new folder in your home directory. This script only prints information; it does not change system settings.

  1. Create and enter a practice folder. 
    mkdir -p "$HOME/bash-labs/lesson-1"
cd "$HOME/bash-labs/lesson-1"
  2. Open report.sh in a text editor such as nano or vim, paste these lines, and save: 
    #!/usr/bin/env bash
printf 'User: '
id -un
printf 'Host: '
hostname
printf 'Kernel: '
uname -srm
  3. Ask Bash to check the syntax, then run it. 
    bash -n report.sh
bash report.sh

    No output from bash -n means Bash found no syntax error; it does not prove the commands will succeed on every machine.

  4. Now give yourself execute permission and launch the file directly. 
    chmod u+x report.sh
./report.sh

Illustrative output

User: learner
Host: devbox
Kernel: Linux 6.8.0 x86_64

Your username, hostname, and kernel version will differ.
