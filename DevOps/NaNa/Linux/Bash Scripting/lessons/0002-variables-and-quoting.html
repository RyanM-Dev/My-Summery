Configuration in, one argument out

Pass Bash values safely

Make a release report configurable, give it an application name with a space, and keep that name intact.

Mission: Build toward reliable scripts for Linux and DevOps workflows such as local checks and CI jobs.

One mental model

A variable is a value; quotes protect its shape

Assignment stores a value. Expansion inserts that value into a command. Double quotes let the value expand while keeping it together as one argument.

app_name='billing api'
printf 'Application: %s\n' "$app_name"
Application: billing api

Write assignments without spaces around =, and use the name without $ on the left. Use $app_name to expand it; braces make the boundary explicit when more text follows, as in ${app_name}_worker.

Quoting changes what the shell does with an expanded value. Double quotes allow expansion and protect spaces; single quotes preserve their contents literally. Bash documents these rules under Quoting and Shell Expansions.

Operational consequence: if a path is /srv/build output, an unquoted expansion may become two words. Pass it as "$path" so the receiving command gets one path argument.

ShellCheck SC2086 explains how to spot many accidental unquoted expansions.

Five-minute practice

Build a configurable release report

The caller supplies uppercase environment settings. The script copies them into descriptive variables, chooses defaults for optional settings, and stops if the app name is missing.

#!/usr/bin/env bash

app_name=${APP_NAME:?Set APP_NAME before running this script}
deploy_env=${DEPLOY_ENV:-staging}
release_tag=${RELEASE_TAG:-manual-run}

printf 'App: %s\nEnvironment: %s\nRelease: %s\n' \
    "$app_name" "$deploy_env" "$release_tag"
  • ${NAME:-default} uses the fallback when the setting is unset or empty.
  • ${NAME:?message} stops with a useful error when a required value is unset or empty.
  • "$app_name" makes the application name one argument to printf.

The Bash manual explains the unset and empty-value behavior in Shell Parameter Expansion.

Save the listing as release-report.sh, then call it with fake release data:

APP_NAME='billing api' DEPLOY_ENV='test' RELEASE_TAG='v1.4.0' bash release-report.sh
App: billing api
Environment: test
Release: v1.4.0

The NAME=value command form sets values for that command's environment. Use export NAME=value when later child processes in the current shell should inherit the setting.
