Check before you act

Check status and prerequisites

Make a script confirm that its release configuration is a readable file before later steps use it.

Mission: Prevent avoidable failures in repeatable Linux and DevOps operations by checking prerequisites early.

One mental model

Commands report success through their exit status

Bash treats exit status 0 as success and a non-zero status as failure. The status is a signal to the next command or script—not a human-readable explanation.

The most recent command's status is available as $?. Read or save it immediately because every new command replaces it.

bash -n release-report.sh
status=$?
printf 'Syntax check status: %s\n' "$status"

A successful syntax check prints status 0; a syntax problem prints a non-zero status. GNU Bash documents the status convention in Exit Status.

Four-minute practice

Preflight a configuration file

The [[ ... ]] test returns status 0 when its condition is true. -f checks for a regular file; -r checks whether it is readable. Join both checks with && so both must pass.

#!/usr/bin/env bash

config_file=${1:-./release.env}

if [[ -f "$config_file" && -r "$config_file" ]]; then
    printf 'Config is ready: %s\n' "$config_file"
else
    printf 'Config is missing or unreadable: %s\n' "$config_file" >&2
    exit 1
fi

Save it as check-config.sh. Use a harmless practice file to see the success path:

printf 'APP_NAME=demo\n' > release.env
bash check-config.sh release.env
Config is ready: release.env

Then try a name that does not exist:

bash check-config.sh missing.env
Config is missing or unreadable: missing.env

The second run exits with status 1. The message goes to standard error, and exit 1 tells a caller or CI step that the preflight failed.

File tests and string tests are documented in Bash Conditional Expressions.
