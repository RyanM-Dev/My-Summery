Known inputs, deliberate branches

Choose an action with if and case

Validate a release file, then print a plan for the selected environment. The lesson script deliberately does not deploy anything.

Mission: Make automation respond predictably to inputs before it performs real operational work.

One mental model

if checks a result; case selects a known value

Use if when a command or test must succeed before the next step. Use case when one named input can select among several known actions.

In Bash, an if condition runs commands and branches when their exit status is zero. case checks patterns in order and runs the first match. See the GNU Bash Manual for Conditional Constructs.

Five-minute practice

Guard a deployment plan

Save this as deployment-plan.sh. It requires a readable release file and accepts only the environment labels you expect.

#!/usr/bin/env bash

manifest=${1:-./release.env}
environment=${DEPLOY_ENV:-staging}

if [[ ! -f "$manifest" || ! -r "$manifest" ]]; then
    printf 'Cannot read release file: %s\n' "$manifest" >&2
    exit 1
fi

case "$environment" in
    dev|test)
        printf 'Plan: run checks; no deployment.\n'
        ;;
    staging)
        printf 'Plan: prepare a staging release.\n'
        ;;
    production)
        printf 'Plan: production requires approval.\n'
        ;;
    *)
        printf 'Unknown environment: %s\n' "$environment" >&2
        exit 2
        ;;
esac
  • The if branch stops before planning when the manifest is missing or unreadable.
  • dev|test is a pattern list: either value matches the same branch.
  • *) catches any value not handled above; ;; ends each branch.

Try an accepted value:

DEPLOY_ENV=test bash deployment-plan.sh release.env
Plan: run checks; no deployment.

Then try DEPLOY_ENV=qa. The script should print an error and exit with status 2. This is an input-validation example; a production deploy needs separate authorization and operational checks.
