## 📦 Installed Is Not Running

`unattended-upgrades` downloads and installs security fixes every day. But installing replaces **files on disk**. The kernel already in memory, and every process that already loaded the old `libc`, keep running the **old code**.

> 💡 **Real-World Example**
>
> Our server has been up for **72 days**.
>
> - 🧠 **Running kernel:** `7.0.0-30-generic`
>
> - 💾 **Installed kernel:** `7.0.0-43-generic`, 13 updates later
>
> - 📋 **`/var/run/reboot-required.pkgs`:** kernels -31 … -43 and **`libc6`**
>
> Every kernel fix from September to November is on disk, but none of it is protecting us.

```mermaid
flowchart LR
    APT["🩹 unattended-upgrades"] -->|"writes"| DISK["💾 /boot/vmlinuz-…-43<br/>new libc.so"]
    DISK -.->|"only after reboot / restart"| RAM["🧠 running kernel -30<br/>processes with old libc"]
```

## 🔎 Is a Reboot Pending?

```bash
cat /var/run/reboot-required /var/run/reboot-required.pkgs 2>/dev/null
uname -r                      # running kernel
ls /boot/vmlinuz-*            # installed kernels
```

To find processes still using deleted (replaced) libraries, run `needrestart` (`apt install needrestart`). It lists the services that need a restart, so you can sometimes avoid a full reboot. The kernel itself always needs one, unless you use live-patching (Ubuntu Pro Livepatch).

## 🔁 A Safe Reboot

1. 💾 **Have a fresh backup** first. See [[DevOps/Server Administration/8. Backups and Restore|Backups]].

2. 📋 **Record what is running now**, so you can compare afterwards.

    ```bash
    docker ps --format '{{.Names}} {{.Status}}' | sort > ~/before-reboot.txt
    ```

3. 🔎 **Check the restart policies.** A container with `restart: no` won't come back by itself.

    ```bash
    docker ps -q | xargs docker inspect -f '{{.Name}} {{.HostConfig.RestartPolicy.Name}}'
    ```

    On our server, the 3 `crypto-interop-spike` containers use `no`.

4. 🔁 **Reboot**, then wait about a minute.

    ```bash
    sudo systemctl reboot
    ```

5. ✅ **Verify.**

    ```bash
    uname -r
    docker ps --format '{{.Names}} {{.Status}}' | sort | diff ~/before-reboot.txt - 
    ```

    The diff shows only `Up` times changing. Anything missing needs `docker compose up -d` in its project directory.

To make this routine, either reboot monthly on a calendar reminder, or let unattended-upgrades do it at night:

```text
# /etc/apt/apt.conf.d/50unattended-upgrades
Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "04:00";
```

## 🐳 Patching Containers

`apt` doesn't touch container images. Each image carries its own OS libraries, frozen at build time.

- 📌 Pin images by digest, so deploys are reproducible.

- 🔁 Re-pin **monthly**, even without an app release. For example, `eclipse-mosquitto:2.1.2-alpine` was rebuilt with new Alpine (OpenSSL) fixes between October and November 2026, under the **same tag**.

- 🔎 Scan to see which images have known CVEs:

    ```bash
    trivy image eclipse-mosquitto:2.1.2-alpine
    ```

### 🧪 Interview Q&A

**Q1:** unattended-upgrades says "All upgrades installed". Is the server patched?

**Q2:** Which two things does a reboot apply that a package install can't?

**Q3:** Why check restart policies before rebooting?

**Q4:** Does `apt upgrade` on the host patch the OpenSSL inside your containers?

> [!answer]- 📋 Answers
>
> **A1:** The packages are, but a running kernel or long-running processes may still use the old code. Check `/var/run/reboot-required`.
>
> **A2:** The new kernel, and the new shared libraries (like `libc`) in every process that had the old ones loaded.
>
> **A3:** Containers with `restart: no` stay down after the reboot, so you need to know which ones to start by hand.
>
> **A4:** No. Each image has its own libraries. Rebuild or re-pull it to get fixes.

## 📋 Quick Reference

| Task | Command |
|---|---|
| Reboot pending? | `cat /var/run/reboot-required.pkgs` |
| Running kernel | `uname -r` |
| Upgradable packages | `apt list --upgradable` |
| Upgrade log | `less /var/log/unattended-upgrades/unattended-upgrades.log` |
| Services using old libraries | `sudo needrestart -r l` |
| Image CVEs | `trivy image <image>` |

## 🧠 Things to Remember

- Installed ≠ running. Reboot to finish patching.
- Back up first, record the state, reboot, then diff.
- Container images need their own patch cycle.

## 💡 Pro Tips

- Show "reboot required" in your shell prompt or the MOTD, so you see it every time you log in.
- Keep every service `restart: unless-stopped`, unless you **want** it to stay down.
