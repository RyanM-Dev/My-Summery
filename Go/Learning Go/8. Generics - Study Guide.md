### 📖 Chapter Summary

Chapter 8 of *Learning Go* (Bodner) introduces Go generics (type parameters): why they exist, how to declare generic functions and types, constraints, type sets (type terms with `|` and `~`), the built-in `comparable` constraint, type inference, and how generics interact with interfaces. Bodner frames generics as a way to **reduce repetitive code** and **restore compile-time type safety** that reflection, `interface{}`, or duplicated functions sacrifice.

Before Go 1.18, authors duplicated algorithms per slice type, used `float64` as a universal numeric type (`math.Max`), or built interface-heavy trees that compile but panic when mixed concrete types are inserted. Generics let you write `Stack[T]`, `Map[T1,T2]`, and `Min[T]` once — with the compiler rejecting invalid instantiations.

*100 Go Mistakes* (Harsanyi) #9 warns against **being confused about when to use generics**: readability first, don't use for one-off cases, don't replace a simple `io.Writer` parameter with `func foo[T io.Writer](<w T>)`, and wait for real duplication before abstracting.

*Go in Practice* (2nd ed., Ch.3) applies generics constraints and type sets in production APIs — factoring collection utilities without reflection, using `comparable` for map keys, and understanding `~int` vs `int` approximations.

This chapter answers: *When does a generic function earn its complexity, and when should I reach for an interface, duplication, or the stdlib `slices`/`maps`/`cmp` packages instead?*

## Part 1: Why Generics — Reduce Repetition, Increase Type Safety

### 📌 Concepts Explained

- **"Don't repeat yourself"** fails in static typing when the *only* difference is the type (`getKeys` for `map[string]int` vs `map[int]string`).
- Pre-1.18 options: **duplicate**, **code generation**, **reflection** (runtime checks), or **interfaces** (lose same-concrete-type guarantees).
- Bodner's **Orderable tree**: `Order(any) int` compiles with mixed `OrderableInt` + `OrderableString` — **panic at runtime**.
- Pre-generics stdlib compromises: `math.Max`/`Min` on `float64`; `sort.Slice` uses reflection.
- Generics restore **compile-time rejection** of bad instantiations.

### 🔧 Bodner — Interface Tree vs Generic Stack

```go
// Learning Go (Bodner) — interface tree: compiles, panics at runtime
type Orderable interface { Order(any) int }
type OrderableInt int
func (oi OrderableInt) Order(val any) int { return int(oi - val.(OrderableInt)) }

var it *Tree
it = it.Insert(OrderableInt(5))
it = it.Insert(OrderableString("nope")) // compiles — runtime panic

// Learning Go (Bodner) — generic stack: compile-time safety
type Stack[T any] struct { vals []T }
func (s *Stack[T]) Push(val T) { s.vals = append(s.vals, val) }
func (s *Stack[T]) Pop() (T, bool) {
    if len(s.vals) == 0 { var zero T; return zero, false } // can't return nil for int
    top := s.vals[len(s.vals)-1]
    s.vals = s.vals[:len(s.vals)-1]
    return top, true
}
```

## Part 2: Type Parameters, Constraints, and Type Sets

### 📌 Concepts Explained

- **Syntax:** `func Name[T Constraint](args)` or `type Name[T Constraint] struct`
- **Instantiation:** `Stack[int]`, `getKeys[string,int](m)` — compile time, type-safe.
- **Constraint:** interface limiting valid types — **methods** and/or **type elements** (type sets).
- **`any`:** all types; no operators guaranteed.
- **Type terms:** `int | float64` — operators must work on **all** listed types.
- **`~int`:** matches `int` and types with underlying type `int` (`type MyInt int`).
- **Constraint-only:** interfaces with type elements cannot be variable types.

### 🔧 Bodner — Generic Functions and Type Sets

```go
// Learning Go (Bodner) — Map/Filter with inference
func Map[T1, T2 any](<s []T1, f func(T1>) T2) []T2 {
    r := make([]T2, len(s))
    for i, v := range s { r[i] = f(v) }
    return r
}
filtered := Filter(words, func(s string) bool { return s != "Potato" }) // T inferred

// Learning Go (Bodner) — type set for operators
type Integer interface {
    ~int | ~int8 | ~int16 | ~int32 | ~int64 |
    ~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~uintptr
}
func divAndRemainder[T Integer](<num, denom T>) (T, T, error) {
    if denom == 0 { return 0, 0, errors.New("cannot divide by zero") }
    return num / denom, num % denom, nil
}
```

### 🔧 Go in Practice — Custom Constraint and `~int` vs `int`

```go
// Go in Practice (2nd ed.) Ch.3 — restrict keys beyond comparable
type intOrString interface { ~int | ~string }

func getKeys[K intOrString, V any](<m map[K]V>) []K {
    keys := make([]K, 0, len(m))
    for k := range m { keys = append(keys, k) }
    return keys
}
// int matches only int; ~int also matches type customInt int
```

| Form | Matches |
|------|---------|
| `int` | Exactly `int` |
| `~int` | `int` + any type with underlying `int` |

## Part 3: Harsanyi #9 — When (Not) to Use Generics

### 📌 Concepts Explained

Harsanyi #9: generics are **never mandatory**. The mistake is abstracting before duplication is real — same spirit as interface pollution (#5–#7).

**Use when:** reusable data structures (stack, heap, tree); functions over slices/maps/channels; factoring behavior that interfaces force you to duplicate per type.

**Don't use when:** you only call an **interface method**; code becomes **harder to read**; it's a **one-off**; you're **prematurely abstracting**.

### 🔧 Harsanyi #9 — Reflection vs Generic `getKeys`

```go
// Common mistake (Harsanyi #9) — runtime type switch, []any return
func getKeysBad(m any) ([]any, error) {
    switch t := m.(type) {
    case map[string]int:
        var keys []any
        for k := range t { keys = append(keys, k) }
        return keys, nil
    default:
        return nil, fmt.Errorf("unknown type: %T", t)
    }
}

// Learning Go / Harsanyi — compile-time safety
func getKeys[K comparable, V any](<m map[K]V>) []K {
    keys := make([]K, 0, len(m))
    for k := range m { keys = append(keys, k) }
    return keys
}
keys := getKeys(m) // infers K=string, V=int
```

### 🔧 Harsanyi #9 — Don't Genericize Interface Calls

```go
// Common mistake (Harsanyi #9)
func writeGeneric[T io.Writer](<w T>) { _, _ = w.Write(getBytes()) }

// Idiomatic — interface is enough
func writeIdiomatic(w io.Writer) { _, _ = w.Write(getBytes()) }

// Valid use — generic linked list; methods CANNOT have type params
type Node[T any] struct { Val T; next *Node[T] }
func (n *Node[T]) Add(next *Node[T]) { n.next = next }
// func (Foo) bar[T any](<t T>) {} // compile error
```

## Part 4: `comparable`, Type Inference, and Generics vs Interfaces

### 📌 Concepts Explained

- **`any` ≠ comparable.** `Stack[T any]` cannot use `==` — switch to `Stack[T comparable]` for `Contains`.
- **Map keys must be comparable** — `map[[]byte]int` is invalid; generics enforce `K comparable`.
- **Inference:** works from arguments (`Filter(words, fn)`). Fails when type param is **return-only**: `Convert[int,int64](a)`.
- **Generics vs interfaces:** interfaces = behavior across types; generics = one concrete type per instantiation (`Pair[T]` both fields same `T`).
- **Performance trap:** converting `func doubleAge(a Ager)` → `func doubleAgeGeneric[T Ager](<a T>)` made trivial calls ~30% slower in Go 1.20 (Bodner) — don't do it for speed.

### 🔧 Bodner — `comparable`, Inference, Interface Pitfall

```go
// Learning Go (Bodner) — comparable enables ==
type Stack[T comparable] struct { vals []T }
func (s Stack[T]) Contains(val T) bool {
    for _, v := range s.vals { if v == val { return true } }
    return false
}

// Inference limit — T2 only in return
func Convert[T1, T2 Integer](<in T1>) T2 { return T2(in) }
b := Convert[int, int64](a) // must specify both

// comparable pitfall — interface holding uncomparable dynamic type PANICS
var a, b Thinger = ThingerSlice{1, 2}, ThingerSlice{1, 2}
Comparer(a, b) // compiles — runtime panic
```

### 🔧 Bodner — Generics + Interface Constraints

```go
type Pair[T fmt.Stringer] struct { Val1, Val2 T }
type Differ[T any] interface { fmt.Stringer; Diff(T) float64 }
func FindCloser[T Differ[T]](<pair1, pair2 Pair[T]>) Pair[T] { ... }
```

## Part 5: When NOT to Use — Limitations and Stdlib Generics

### 📌 Concepts Explained

**Deliberately omitted (Bodner):** operator overloading; type params on methods; variadic type parameters; specialization/currying/metaprogramming.

**Idiomatic guidance:** don't rewrite everything to generics; use `any` not `interface{}`; benchmark before iface→generic conversion.

**Stdlib generics (Go 1.21+):** `slices` (`Sort`, `SortFunc`, `Equal`, `Clone`, `Insert`, `Delete`), `maps` (`Clone`, `Copy`, `Equal`), `cmp` (`Ordered`, `Compare`, `Less`), `sync.OnceValues`.

### 🔧 Bodner — Generic Tree + Stdlib Preference

```go
// Learning Go (Bodner) — behavior via function, not interface chaos
type OrderableFunc[T any] func(t1, t2 T) int
type Tree[T any] struct { f OrderableFunc[T]; root *Node[T] }
peopleTree := NewTree(func(a, b Person) int {
    return strings.Compare(a.LastName, b.LastName)
})

// 2026 senior standard — stdlib over custom generics
slices.SortFunc(people, func(a, b Person) int { return cmp.Compare(a.Age, b.Age) })
clone := maps.Clone(m)
```

### 🔧 Methods Cannot Chain Generic Type Params

```go
// DOES NOT COMPILE — use standalone Map/Filter functions instead
// func (fs functionalSlice[T]) Map[E any](<f func(T>) E) functionalSlice[E]
mapped := Map(fs, func(s string) int { v, _ := strconv.Atoi(s); return v })
```

## Part 6: Combined Best Practices + `makePointer[T]` Tie-In

### 📌 Concepts Explained

**Decision flow:** (1) `slices`/`maps`/`cmp` solve it? → stdlib. (2) One-off? → concrete. (3) Calling interface methods? → interface. (4) Real duplication? → generics. (5) Readability suffers? → duplicate.

**`makePointer[T]` (Bodner Ch.6):** first practical generic — returns `*T` from a literal/value; pairs with optional `*string` JSON fields.

### 🔧 Bodner Ch.6 → Ch.8 — `makePointer`, `Min`, Constrained Keys

```go
// Learning Go (Bodner) — pointer helper from Ch.6, perfected in Ch.8
func makePointer[T any](<t T>) *T { return &t }

type Person struct {
    FirstName string; MiddleName *string; LastName string
}
p := Person{FirstName: "Perry", MiddleName: makePointer("Perry"), LastName: "Mason"}

// Generic Min — Bodner exercise + 2026 cmp
func Min[T cmp.Ordered](<a, b T>) T {
    if cmp.Less(a, b) { return a }
    return b
}

// Constrained map keys — comparable + GiP custom set
type IntOrString interface { ~int | ~string }
func invertMap[K IntOrString, V comparable](<m map[K]V>) map[V]K {
    out := make(map[V]K, len(m))
    for k, v := range m { out[v] = k }
    return out
}
```

### 📊 Decision Table — Interface vs Generics vs Duplication

| Situation | Best choice |
|-----------|-------------|
| Call `Write()` on parameter | `io.Writer` (Harsanyi #9) |
| Sort typed slice | `slices.Sort` / `slices.SortFunc` |
| Min across numeric types | `Min[T cmp.Ordered]` |
| One-type binary tree | Concrete type first |
| Keys from any comparable map | `getKeys[K comparable, V any]` |
| JSON `null` vs `""` | `*string` + `makePointer("x")` |

> [!success]- 📋 Answers — Part 8
> **A1:** Reduce duplicated algorithms/data structures while keeping compile-time safety. Pre-1.18: per-type duplication, reflection (`sort.Slice`), `any` + type switches (runtime errors), interface workarounds that panic on mixed concrete types.
>
> **A2:** `any` = any type, no operators guaranteed. `comparable` = supports `==`/`!=`. Use `comparable` for equality and map keys. Slices, maps, functions are not comparable.
>
> **A3:** Type set = union in constraint (`int | string`). `int` = exactly `int`. `~int` = `int` plus types whose underlying type is `int`.
>
> **A4:** Infers from arguments when possible (`getKeys(m)`). Explicit when param appears only in return: `Convert[int,int64](a)`.
>
> **A5:** Readability first. Use when real duplication exists. Don't replace interface params when you only call methods. Don't abstract prematurely — parallels interface pollution.
>
> **A6:** Interfaces for behavior ("has these methods"). Generics for type-parametric code where all slots share one concrete type. `io.Writer` not `func foo[T io.Writer]`.
>
> **A7:** Language design choice. Type params go on generic receivers (`Stack[T]`), not individual methods. Use package-level generic functions.
>
> **A8:** `slices`, `maps`, `cmp` (plus `sync.OnceValues`). Use stdlib unless domain needs behavior they lack.
>
> **A9:** `func Min[T cmp.Ordered](<a, b T>) T` with `cmp.Less`. `getKeys` needs `K comparable` because Go map keys must be comparable — `[]byte` keys are illegal; compiler enforces at instantiation.
