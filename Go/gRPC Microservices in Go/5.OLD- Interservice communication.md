### 🔧 Synchronous Communication & Stubs

- **Babal's Explanation**: When the Order service needs to charge a customer, it calls a local **stub**. This stub marshals the request into binary and sends it across the wire to the Payment service.
- **Shuiskov Nuance**: Shuiskov highlights that stubs aren't just for messages; they define the **entire API contract**. In Go, this means the compiler generates both the client interface (`NewMetadataServiceClient`) and the server interface (`MetadataServiceServer`) to ensure both sides stay in sync.
- **2026 Modern Standard**: We use **Buf** to manage these stubs. Instead of manually copying `.pb.go` files, we treat generated stubs as versioned Go modules imported via `go get` [History, 120].

### 🔧 Load Balancing: Server-Side vs. Client-Side

- **Server-Side (Default for K8s)**: The client makes a call to a virtual IP (like a Kubernetes Service). The load balancer tracks the health of backend pods and fair-routes the traffic.
- **Client-Side (High Performance)**: The client queries a **Service Registry** (like Consul) to get a list of all IP addresses for the Payment service. The client then uses an algorithm (e.g., Round Robin) to pick an instance.
- **Decision Logic**: Shuiskov notes that while Server-side LB simplifies application code, Client-side LB offers better performance because it removes the "extra hop" of an intermediate proxy.

💡 Pro Tips & Best Practices (Combined)

1. **Stop Using `grpc.Dial`**: As of 2026, `grpc.Dial` is deprecated. Always use `grpc.NewClient` for non-blocking, modern connections.
2. **Stubs as Dependencies**: Never manually copy `.pb.go` files between services. Host them in a dedicated `proto` repo and import them as modules.
3. **Prefer Buf over Protoc**: `buf generate` is faster, lint-friendly, and handles complex imports better than raw `protoc` [History].
4. **No Single Point of Failure**: When possible, evaluate if **Client-side LB** is worth the configuration overhead to remove the central proxy bottleneck.
5. **Context is Mandatory**: Even if your `.proto` doesn't define it, gRPC stubs require `context.Context`. Use it to propagate deadlines and trace IDs.
6. **Unimplemented Embedding**: Always embed `Unimplemented<Service>Server` in your server adapters to ensure forward compatibility.
